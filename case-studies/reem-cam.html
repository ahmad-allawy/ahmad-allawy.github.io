WebRTC / Local networking

Running multi-camera streaming on a local network

Connect phone cameras to browser dashboards over one Wi-Fi network without relying on cloud services.

Node.js React WebRTC mediasoup

01 / The challenge

Multiple cameras, one local network

The goal was to use phones as live cameras and view their feeds from a browser on the same Wi-Fi network. The system was designed to work locally, without a cloud service or database.

02 / The investigation

The network path is part of the camera feature

Mobile browsers require a secure origin for camera access. A phone reaches the host through its LAN IP rather than localhost, so HTTPS must be available on that address. Media traffic also depends on firewall rules and advertising the correct network interface.

03 / The implementation

Route streams locally and let viewers choose quality

A Node.js server hosts the client over HTTPS and coordinates sessions through Socket.IO. mediasoup acts as the WebRTC SFU between camera phones and browser viewers. Cameras publish simulcast layers, allowing a viewer to switch quality per tile without asking the camera to restart its stream.

04 / The outcome

A browser dashboard without cloud dependencies

Phones on the same LAN can publish camera feeds that appear in a responsive viewer dashboard. The project documents a target glass-to-glass latency of about 100–300 ms on a healthy LAN; actual results depend on the network and devices.
